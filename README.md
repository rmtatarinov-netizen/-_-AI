# Telegram AI Bot

Telegram-бот-ассистент на Python (pyTelegramBotAPI) с подключением к LLM API.
Каждый пользователь имеет собственный контекст диалога; провайдер ИИ переключается командой в чате.

## Структура проекта

| Файл | Назначение |
|---|---|
| `bot.py` | Основной файл: хендлеры команд и диалога |
| `config.py` | Настройки, справочник провайдеров, чтение `.env` |
| `api_client.py` | Общение с API (OpenAI-совместимый SDK) |
| `context_manager.py` | Хранение контекста и выбранного провайдера в памяти |

## Установка

```
pip install -r requirements.txt
copy .env.example .env   # (Windows) или cp .env.example .env
```

Заполните `.env` (ключи хранятся ТОЛЬКО здесь, не в коде):

```
BOT_TOKEN=токен_от_botfather
PROXYAPI_API_KEY=ключ_proxyapi
GENAPI_API_KEY=ключ_genapi
API_PROVIDER=proxyapi          # провайдер по умолчанию (необязательно)
TELEGRAM_PROXY=                # необязательно: см. раздел «Прокси» ниже
```

## Запуск

```
python bot.py
```

Логи пишутся в консоль и в `bot.log` (ротация: файл до ~5 МБ, 3 резервных копии).

## Прокси для Telegram (если api.telegram.org блокируется)

Признак блокировки — ошибки `SSLError: UNEXPECTED_EOF_WHILE_READING` при запросах к
`api.telegram.org`. Решение — задать прокси в `.env`:

```
TELEGRAM_PROXY=socks5h://127.0.0.1:1080
```

поддерживаются `socks5h://`, `socks5://`, `http://` (для SOCKS нужен пакет `pysocks` из requirements).
Бот подхватит его при старте (`telebot.apihelper.proxy`); на запросы к ProxyAPI/GenAPI это не влияет.
Также можно запускать бота на сервере без блокировок или через системный VPN/TUN.

Все исходящие в Telegram идут через `send_with_retry` (3 попытки, паузы 2/5/10 с) — временные
обрывы TLS переживают без потери ответов.

## Безопасность и токен

- `BOT_TOKEN` и ключи API хранятся только в `.env`; не коммитьте `.env`, `bot.log*` и `.gitignore` с ними при переходе на git.
- Логи маскируют токен: `TokenMaskFormatter` в `bot.py` заменяет его на `***BOT_TOKEN***` даже внутри traceback.
- Telegram API устроен так, что токен всегда часть URL, поэтому не пересылайте сырые логи/скриншоты ошибок — сначала проверяйте на токен.
- Если токен всё же засветился — немедленно отзывайте новый у @BotFather (`/mybots` → `Revoke`) и обновляйте `.env`.

## Команды бота

- `/start`, `/help` — приветствие и подсказка
- `/reset` или фраза «очистить контекст» — стирание истории диалога
- `/api` — показать текущий провайдер и список доступных
- `/api proxyapi` / `/api genapi` — переключение провайдера

## Переключение между провайдерами

| Провайдер | Base URL | Модель | Ключ в .env |
|---|---|---|---|
| `proxyapi` | https://api.proxyapi.ru/v1 | openai/gpt-5-mini-2025-08-07 | `PROXYAPI_API_KEY` |
| `genapi` | https://proxy.gen-api.ru/v1 | gpt-4.1-mini | `GENAPI_API_KEY` |

Как это работает:

1. Бот от всех ответов использует провайдер по умолчанию (`API_PROVIDER` из `.env`, либо `proxyapi`).
2. Пользователь пишет `/api genapi` — бот проверяет, что в `.env` задан `GENAPI_API_KEY`, и переключает **этого пользователя** на genapi.
3. Выбор провайдера хранится в памяти per-user и не влияет на других пользователей.
4. История диалога при переключении сохраняется — новая модель продолжит диалог с тем же контекстом (последние 20 сообщений).
5. `/api` без аргумента показывает текущего провайдера; `/api proxyapi` — возвращает обратно.
6. Смена провайдера не очищает контекст; для очистки — `/reset`.

Оба эндпоинта OpenAI-совместимы (авторизация `Authorization: Bearer <ключ>`), поэтому переключение — это просто смена `base_url`, ключа и имени модели в конфиге.

## Добавление нового провайдера

Дописать словарь в `config.PROVIDERS` (`base_url`, `key_env`, `model`, `supports_reasoning`) и добавить ключ в `.env` — код менять не нужно.
